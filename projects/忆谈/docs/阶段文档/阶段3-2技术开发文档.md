# 阶段 3-2 技术开发文档

## 家人阅读与历史恢复

2026-11-09 产品经理选择千问 Plus 的叙事风格，后续写作与写作审查统一使用 `qwen3.7-plus` 思考模式；既有正文保留。阶段继续实施家人功能。

- 管理者选择当前章节和照片，预览后明确确认展示。展示正文保存独立加密快照，后续重新生成、历史恢复不会自动改变家人所读内容。
- 家人通过一次性邀请加入，填写称呼，获得独立 HttpOnly 会话；邀请七天有效，服务端保存摘要。邀请由管理者自行复制传递，地址中令牌使用 fragment，进入页面后立即移出地址栏。
- 家人接口仅返回展示快照、获准照片及留言；原话、核对事项、管理接口均不可访问。原声按整次访谈单独授权，界面明确可能包含本次访谈其他内容。
- 邀请可撤销、成员可移除，撤销后每个读取和写入接口立即拒绝；展示可取消，正文、留言和旧展示版本均保留。
- 留言与展示版本关联，家人可删除自己的留言，管理者可删除留言；使用幂等请求编号避免重复提交。
- 管理者可查看历史正文，确认后恢复；恢复前保存当前正文，恢复不自动更新家人展示。原话、录音和核对记录保留。
- 所有数据库变更增加新表，保留既有数据。写入采用事务和幂等标识；错误沿用 `error.code/message`。邀请兑换限一次，成员权限每次由后端核验。

### 新增接口契约

全部接口前缀 `/api/v1`。管理接口要求管理者会话，家人接口要求独立家人成员会话。未登录返回 401，资源不可见返回 404，过期或已使用邀请返回 410，内容变更需要重新预览返回 409，参数错误返回 400。

| 方法与路径 | 请求 | 响应 |
| --- | --- | --- |
| GET `/profiles/{id}/family` | 无 | 当前展示、成员、邀请与留言 |
| POST `/profiles/{id}/family/preview` | chapter_ids、photo_ids、allow_audio | 展示内容、内容摘要 digest |
| POST `/profiles/{id}/family/publish` | 同上、digest、request_id | 展示版本 ID |
| DELETE `/profiles/{id}/family/publication` | 无 | ok |
| POST `/profiles/{id}/invitations` | request_id、allow_audio | 邀请 ID、令牌、有效期 |
| DELETE `/invitations/{id}` | 无 | ok |
| POST `/invitations/redeem` | token、name、request_id | profile_id，设置独立家人 Cookie |
| DELETE `/profiles/{id}/members/{member_id}` | 无 | ok |
| GET `/family/reading` | 无 | 获准展示、成员称呼、照片和留言 |
| GET `/family/photos/{id}`、`/family/audio/{call_id}` | 无 | 获准媒体 |
| POST `/family/comments` | chapter_id、publication_id、text、request_id | 留言 ID |
| DELETE `/family/comments/{id}` | 无 | ok，校验作者或管理者 |
| POST `/family/logout` | 无 | ok，清除家人会话 |
| GET `/calls/{id}/editions` | 无 | 历史正文列表 |
| POST `/calls/{id}/editions/{edition_id}/restore` | confirm、request_id | ok |

手机页面采用现有暖色、书页与卡片样式。管理页 `/profiles/[id]/family`，邀请页 `/join`，家人阅读页 `/family`；历史版本入口位于章节阅读页。真实数据验证覆盖重复兑换、撤销、越权、留言幂等、发布快照隔离和重启恢复；浏览器检查四种手机宽度及刷新恢复。

## 实施契约

- 原始转写按行赋予稳定编号，保持说话人与时间信息；分批提取完整事件，记录背景、经过、结果、人物、时间、地点、衔接关系与多处原文。每一行均有事件归属或排除原因。
- 全局规划检查人物、时间和地点，所有事件必须分配给章节或明确暂存核对；有歧义的主体、年份、因果和听写词不能作为确定事实发布。
- 写作接收完整转写、全局人物说明和章节事件；逐章分批生成全部事件，保留前文，不按章节或段落数量裁剪。
- 模型输出结束原因为 length 时，明确记录未完成，缩小事件批次继续处理；无法继续时任务失败，保留原文、过程记录及已有正文。禁止静默截断输入、输出或保存结果。
- 每个句子关联多条精确原文。结构、引用、事件覆盖由确定性代码校验；使用千问 Plus 做事实、指代、冲突和阅读连贯性审查，失败后有限修订并重新审查；未通过不得发布。家人展示另需管理者预览确认。
- 生成过程及模型用量在本地加密保存，数据库保留执行状态。添加独立证据表保存段落多处来源，兼容已有章节接口和数据。
- 写作最终审查通过后以事务保存全部章节；已有正文先保存加密版本，失败不替换。验收语料使用新生成记录，保留旧稿。
