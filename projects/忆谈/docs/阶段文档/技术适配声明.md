# 技术适配声明

## 1. 产品形态判断
- 产品类型与核心任务：子女给 60 岁以上的老人买一份回忆录。老人在浏览器里开口讲，AI 连续陪聊，最后整理成一本能对上原话的书。这次先在你自己电脑上跑通。
- 核心交互：多轮连续语音，加上事后确认。通话中老人可以打断。通话后家属看章节、核对不确定的事实。印刷下单这次不做。
- 开发路径：纵向切片。能不能聊、聊完留不留得住，要在页面上听一次才算数，不能只交一份接口。
- 验收界面：纵向切片界面。从阶段 2-1 起，建档、同意、通话、回放都在会留下来的页面上做。阶段 3 在这些页面上继续，不另起一套，也不把它们废掉。需要你确认。
- 上线套餐：免费体验版，但这次不部署。台账 D9 是复用小红书标题助手的环境；D17 是先在本机跑通。
- 当前阶段范围：阶段 3-3 手机 HTTPS 与实体设备验证，具体范围见阶段 3-3 技术开发文档。

## 2. 采用的默认方案
- Python 3.12：本机有 Python 3.12.15。建项目时用它，不用系统自带的 3.13。
- FastAPI：建档、同意、开始通话、查进度、读章节，都做成可测试的接口。
- Pydantic：档案、章节、核对项、报错都做结构校验。模型没按字段返回，就当失败，不把半截文字当成一章。
- pytest：使用实际数据库与接口验证同意、保存、权限和重启；模型效果使用真实调用验证。
- Git：工具包已经是仓库。密钥文件继续忽略。
- 国内模型由后端调用：连续对话使用豆包实时语音，回忆录事件整理、写作、记忆与审查使用 qwen3.7-plus 思考模式，写书转写使用通义听悟。页面不保存密钥。
- 邀请码换 Cookie：第一张表就记下这份资料属于谁。一个人只能看到自己家庭的订单。
- 录音、照片放在本机数据目录，不塞进数据库，也不进仓库。文字记录进数据库。
- 整理章节用「提交后拿任务号，再查进度」。通话本身是一路实时语音，不走网页上的逐字流。

## 3. 触发的按需模块
工坊方案里选中的组件，按下面落成。没选的默认不做。

| 方案里的组件 | 结论 | 在这个产品里落成什么 |
| --- | --- | --- |
| s01 循环、s02 工具、s15 把它们装在一起 | 采纳，收窄用法 | 一个后端服务。通话由代码决定何时开始、何时结束。通话中不让模型自己挑工具。通话后的整理也由代码按步骤调用 |
| s03 权限 | 采纳 | 没点同意就不听、不记。删除整单要再确认。印刷这次不做，所以先不做「确认后才下单」 |
| s04 留痕 | 采纳 | 每次整理、每次同意或拒绝，记一行：时间、是谁、结果。不记原文，不记录音 |
| s05 任务规划 | 采纳为固定步骤 | 建档、同意、通话、整理、核对，写成代码里的状态。不让模型自己列计划 |
| s06 子代理 | 不采纳 | 访谈和写作用两段提示词、同一次整理任务。不另开一个会自己行动的写手。以后若一章长到一次整理装不下，再拆 |
| s08 上下文压缩 | 采纳 | 每次通话开场放入上次摘要、还没问完的缺口、不想聊的话题。不把整段录音塞进对话 |
| s09 记忆 | 采纳 | 人物、地点、时间、事件存在数据库，每条带来源和时间 |
| s10 任务、s11 后台整理 | 采纳 | 通话结束后的转写和写章节记成任务。关掉再打开还能查。先不另装任务队列软件；若单次整理经常超过 10 分钟且重启后续不上，再加 |
| s12 定时提醒 | 这次不采纳 | 小程序订阅消息这次不做。不做定时发消息 |
| s17 自动判断书写完 | 不采纳运行时自动成书 | 覆盖度用代码算一个数字给家属看。模型不能自己宣布这本书写完了 |

方案放弃的 s07 技能库、s13 多代理团队、s14 插件协议、s16 固定流程引擎：不做。

另外这些按需模块会用到：

- SQLite：有家庭、通话、录音、两路文字、记忆、章节、核对项，还要按人分开。2-1 就建库。数据读写集中在一处，以后若上线再换云数据库。现在不上云。
- 本地文件目录：2-1 起保存录音和照片。录音加密后存放，钥匙在本地环境文件里。
- 不引入：知识库、Word、PDF、看图模型、印刷接口、微信小程序。

## 4. 偏离或暂缓的默认方案
- 默认可以先做接口、最后再做页面。替代：从 2-1 就做会留下的网页。原因：连续对话要听得见、录音要找得到。影响：2-1 就要在电脑和手机宽度上都能打开这一页。你确认这是正式页面的起点。
- 前端手册里有一句：语音产品的第一版优先「按住说话」，边听边说以后再做。不按这句做。原因：你在阶段 0 已经定了这次用豆包实时语音，老人可以打断。影响：2-1 就做连续对话。外放会不会把自己的声音听进去，第一通真机通话时听一次，听出问题再改接法，不退回一问一答。
- 默认上线到腾讯云。暂缓。原因：你定了先在自己电脑上跑通。影响：这次不做注册、实名、公网地址。阶段 3 通过后直接收尾。环境以后仍复用已有的免费体验版，不开新环境。
- 终局的微信小程序、精装印刷、定时提醒、整本排版、家族关系图、大事年表、真人编辑：暂缓。原因：这次范围里没有。稿件仍留一个「待人工审校」状态，这轮不接人。影响：不挡住 2-1 到 2-3 的验收。
- 老照片：可以上传、留下。暂缓看图编故事。原因：照片里的人和时间以老人亲口说的为准。重新评估：真有一通通话需要拿照片当问题，再单报价看图模型。
- 境外实时语音、通义实时语音：不用。原因：声音不出境；通义这款公开写明音频历史大约最多 300 秒。主对话只用豆包实时语音。

## 5. 强制底线检查
- 密钥与隐私：密钥保存在后端环境文件，不进入页面、仓库或对话；日志不记录密钥、完整原文、录音和照片。各阶段通过脚本检查。
- 数据与任务可恢复：档案、通话、任务进入数据库，录音与照片保存在本地目录；家人快照、留言及历史正文持久化。各阶段执行重启恢复检查。
- 输入输出校验：档案、章节、核对项使用结构校验；照片校验类型、大小及文件名。模型输出使用 Pydantic 校验。
- 错误与日志边界：接口统一返回错误结构，保留已保存的录音及文字，页面提供后续操作提示。
- 测试与真实模型验收：每个子阶段先跑自动化测试，再做真实调用。没有真结果不能说这一段完成。豆包实时语音看不清一次会不会超过 100 元时，只领试用，不转正式付费。DeepSeek 和旁路转写若可能让当月超过 100 元，先报价，你同意才继续。

运行环境：后端使用 Python 3.12 虚拟环境，前端使用 Node.js v26.10.0。网页 HTTP 端口 3011、手机 HTTPS 端口 3443、后端回环端口 8011。模型凭证已配置，实际调用证据保存在各阶段证据包。

## 6. 需要产品经理决定的问题

## 7. 子阶段规划
- 依据：这次做浏览器里的连续访谈，并留下录音、两路文字、记忆和可对原话的章节。不做小程序，不做印刷，不上线。开发路径是纵向切片，所以每一段都在页面上能点。
- 阶段 2-1：建档并打通一通短通话。家属填老人怎么称呼、出生年、籍贯、家里人、想聊和不想聊的事，可以上传照片。老人点同意后，浏览器里和豆包连续说一小段，可以打断。通话结束，录音、豆包听到的文字、写书用的另一路文字都在。关掉再打开还在，而且只能看到自己家庭的。验收时你自己说几句，听到 AI 接话，并能播放留下的录音。
- 阶段 2-2：把这一通整理成记忆和一章草稿。每段能点开对应的原话。年份、人名、两路文字对不上的地方进核对队列。验收时你读这一章，抽几句对原话，并对 5 到 10 段打分。
- 阶段 2-3：第二次通话开场带上上次摘要。没点同意时不产生录音。你故意说一句银行卡号，它不写进书，也不记进记忆。核对队列可以确认、驳回或修改。验收时你走这三件事，并确认重启后记录还在。
- 阶段 3-0：编写前端适配声明，依据竞品截图确认家庭纪念册视觉、“回忆录、家人、我的”结构和家人阅读权限，在现有工程中继续开发。
- 阶段 3-1：完成书封、目录、独立阅读、相册、照片访谈入口、我的页面及真实访谈出稿流程，补齐整理任务持久化与幂等。手册里的前端子阶段 1 和 2 合并到这里，代表页面由产品经理确认。
- 阶段 3-2：完成断线、重试、历史、核对与恢复；支持同一 Wi-Fi 邀请家人阅读和留言，管理选定章节、照片及单独授权的原声，邀请和成员可撤销；独立浏览器会话验证隔离与持久化。访问范围已于 2026-11-09 确认，后续上线支持异地。产品经理验收通过，实体双设备及录音与逐字稿时间关系随阶段 3-3 手机流程验证。
- 阶段 3-3：iPhone Safari、Android Chrome 真机验证麦克风、外放、字号、软键盘与安全区域。阶段 3 全部页面以 390px 手机设计，验收 360、375、390、430px，暂不适配桌面与平板；此范围由产品经理于 2026-11-09 明确指定。手机开麦克风需要本地安全证书，由 AI 准备并说明手机信任步骤。
- 阶段 4：不做。这次不上线。
- 阶段 5：阶段 3 通过后收尾，写清怎么在自己电脑上启动和验证。
- 调整规则：某一段验收时如果要合并、拆开或增减，先改这一节，再记进项目状态的阶段历史，然后才写下一段的开发文档。
