# 阶段2-1技术开发文档｜建档并打通一通短通话

> 配套文档：`docs/PRD/PRD.md`、`docs/阶段文档/技术适配声明.md`、通用技术栈手册第二、三部分。
> 本文档只覆盖阶段 2-1。不写章节、记忆图谱、第二次通话摘要、核对队列、小程序、印刷。

手册第二、三部分已对账，无冲突。第十一节写本地可以暂不登录；本产品台账已定邀请码，按台账做登录。

## 一、阶段目标
- 交付范围：家属用邀请码进入，给一位老人建档，可上传照片。老人点同意后，浏览器里和豆包连续说一小段，可以打断。通话结束后留下老人原声、AI 回话、豆包听写、写书用的另一路转写。关掉再打开还在，别人看不到。
- 阶段产物：本机网页、后端接口、数据库、加密后的录音和照片、自动化测试。
- 验收标准：你能自己建档、点同意、说几句并听到 AI 接话，然后播放留下的录音。没点同意时不产生录音。没有豆包钥匙时，页面说明通话还不能开始，不得假装已经接通。
- 明确不做：记忆抽取、章节草稿、事实核对、开场摘要、订阅提醒、印刷、小程序、看图编故事。
- 本阶段打通的主链路片段：登录 → 建档 → 同意 → 连续通话 → 两路文字和录音落盘 → 回放。

## 二、技术适配摘要
- 引用《技术适配声明》第 7 节的阶段 2-1。
- 本阶段采用：Python 3.12、FastAPI、Pydantic、pytest、邀请码 Cookie、Next.js 页面。
- 本阶段启用：SQLite、本地加密文件、豆包实时语音、豆包流式语音识别。
- 本阶段偏离/暂缓：不上云；不看图；不写书。
- 开发路径：纵向切片。这一页会留到正式产品。

## 三、技术栈与模型
- 后端：FastAPI。前端：Next.js 14、TypeScript、Tailwind。数据库：SQLite。
- 连续对话：豆包实时语音，模型号 `1.2.6.1`，接口 `wss://openspeech.bytedance.com/api/v3/duplex/realtime/dialogue`。
- 旁路转写：豆包流式语音识别 2.0 小时版，资源号 `volc.seedasr.sauc.duration`。
- DeepSeek 这一段不调用。

## 四、环境与配置
- 配置在 `backend/.env`，样例在 `backend/.env.example`。真实钥匙不进仓库。
- 你要准备的是火山引擎豆包语音的 API Key，填到 `DOUBAO_API_KEY`。没有钥匙时，建档仍可用，通话会明确失败。
- 邀请码在 `INVITE_CODE`。本机默认写在 `backend/.env`，不要发到对话里。
- 后端端口 8011，网页端口 3011。

## 五、项目结构
- `backend/app`：接口、数据库、豆包通话、加密。
- `backend/tests`：不联网的自动测试。
- `frontend`：登录、建档、通话和回放。
- `scripts/restart-check.sh`：重启后记录还在。
- `scripts/smoke.py`：有钥匙才做一次真实接通，并自己写冒烟记录。

## 六、数据、资产与状态
- 持久化用 SQLite，因为有家庭、通话、文字，还要按人分开。照片和录音加密后放在数据目录，库里只存路径。
- 表：owners、sessions、profiles、photos、calls、audio_assets、transcripts、audit_logs。归属字段从第一张业务表就有。
- 通话状态：live → processing → ready 或 failed。失败也保留已经录下的声音。
- 没点同意：不建通话，只在审计里记一次「拒绝」，不记原话。

## 七、API / 工具设计
- `POST /api/v1/auth/login`：邀请码。成功写入 HttpOnly Cookie。错误 `invite_invalid`。
- `POST /api/v1/auth/logout`：退出。
- `GET /api/v1/me`：当前是否已登录，以及语音钥匙是否已配置（只返回是或否）。
- `POST /api/v1/profiles`：建档。字段：称呼、出生年、籍贯、家里人、想聊、不想聊。
- `GET /api/v1/profiles`、`GET /api/v1/profiles/{id}`：只返回自己的。
- `POST /api/v1/profiles/{id}/photos`：jpg、png、webp，最大 10 MB，核对真实文件头。
- `POST /api/v1/calls`：必须 `consent: true`，否则 `consent_required`，不建通话。
- `GET /api/v1/calls/{id}`：状态、两路文字、有没有录音。
- `GET /api/v1/calls/{id}/audio/{kind}`：kind 为 user 或 assistant，返回可播放的 wav。
- `WS /api/v1/calls/{id}/live`：浏览器把 16 kHz 单声道 PCM 送进来，后端转给豆包；豆包的文字和 24 kHz 声音送回页面。结束时服务端收尾。这是实时通道，不是 SSE。
- 错误一律 `{"error": {"code", "message"}}`。
- 通话中不向模型开放工具。整理这一段也不交给模型自己决定。

## 八、Prompt 设计
- 只有一份访谈提示词：`backend/app/prompts/interviewer.txt`。
- 角色是忆谈的 AI 访谈者。先说明自己是 AI、由家人安排。先回应再偶尔追问。不编造自己的经历，不问银行卡和证件，不给医疗法律投资建议。
- 这一段不解析成章节。豆包返回的听写和回话按原文存进 transcripts。

## 九、验收界面或纵向切片（按需）
- 纵向切片界面，会保留。
- 页面：登录、建档列表、老人档案、通话。
- 电脑和手机宽度都要能用。通话页只有同意、一个大按钮和结束。
- 功能上限：建档、一张照片、一通短通话、回放。没有章节页。

## 十、测试要求
- mock：登录失败与成功、看不到别人的档案、坏照片被拒绝、未同意不建通话、加密能解回、假豆包把录音和两路文字留下、错误格式统一。
- 真实冒烟：有 `DOUBAO_API_KEY` 时，`scripts/smoke.py` 只做一次接通并马上挂断，把结果写入冒烟记录。没有钥匙不写假记录。
- `scripts/restart-check.sh` 写入一条档案，杀掉进程再读回称呼。

## 十一、验收清单
- 打开网页，用本机邀请码进入。
- 填一位老人的称呼并保存，刷新后还在。
- 不勾同意就点开始，页面告诉你还不能录音，档案里没有这通通话。
- 勾同意后说一两句。听到 AI 接话。结束后能播放老人原声。
- 页面上能看到豆包听写和另一路转写。

## 十二、风险与待确认项
- 没有豆包钥匙时，真实通话不能验收。这不是失败造假，状态记为待验。
- 豆包实时语音按 token 计费。冒烟只接通一下。若控制台显示会超过当月 100 元，先停。
- 外放可能把自己的声音听进去。第一通若发生，再改接法，不退回按住说话。
- 改动影响：你第一次可以在自己电脑上建档和通话。后续阶段在这些表上加记忆和章节，不换一套库。
- 必须由产品经理决定的问题：无。
