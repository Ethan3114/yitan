# 前端适配声明

日期：2026-11-09。阶段：3-0。状态：产品经理已验收通过。

## 1. 项目判断

- 产品：老人通过连续语音讲述经历，家属管理档案、阅读回忆录、查看原话并核对事实。
- 用户：60 岁以上老人和负责建档、审阅的家属。老人通话时只需处理录音同意、开始和结束。
- 终端：手机浏览器，老人、管理家属与受邀家人全部使用手机界面。以 390px 为设计基准，验收 360、375、390、430px 手机宽度。电脑运行服务并保存数据，手机通过同一局域网安全连接电脑。
- 现有工程：阶段 2 的页面会保留，继续使用现有工程、路由和业务数据。
- 本阶段交付：页面、交互、接口衔接和验收约定。本阶段仅更新文档。
- 写作：产品经理已于 2026-11-09 表示现有写作效果可以，按 D19 继续使用时间节点写作及前后两章展示。

## 4. Agent 状态与接口契约

### 状态映射

| 状态 | 后端或浏览器依据 | 显示与动作 |
| --- | --- | --- |
| `idle` | 尚未创建通话或整理任务 | 显示开始条件 |
| `submitting` | 正在提交创建请求 | 显示正在连接或提交，禁用重复操作 |
| `queued` | 持久化整理任务已受理，尚未执行 | 显示等待整理 |
| `running` | 整理任务记录为执行中 | 显示真实步骤：转写或写作；不显示虚构百分比 |
| `streaming` | WebSocket 收到 `ready`，音频通信进行中 | 显示正在通话和结束按钮 |
| `waiting_user` | 未取得录音同意，或事实状态为 `open` | 老人同意后才能采集声音；家属核对不阻止下一次通话 |
| `succeeded` | 通话 `ready` 或整理任务成功 | 分别显示通话已结束、章节已写成，通话结束不代表章节完成 |
| `partially_succeeded` | 已保存录音或章节，同时有失败步骤 | 明确列出已保存内容和可重试步骤 |
| `failed` | 通话 `failed`、任务失败或协议 `error` | 显示可理解的原因，保留已保存内容 |
| `cancelled` | 后端确认取消 | 当前整理接口无取消能力，此状态暂不提供操作入口；结束通话按通话结束处理 |
| `disconnected` | 连接关闭且未收到结束结果 | 停止采音、释放设备，按原 ID 查询状态 |
| `stale` | 状态查询失败或返回未知枚举 | 显示暂时无法确认状态，允许重新查询 |
| `loading` | 首次数据请求尚未结束 | 显示正在读取 |
| `empty` | 请求成功且确无内容 | 分别提示建立档案、开始访谈或等待整理 |
| `permission_denied` | 未登录或后端拒绝访问 | 引导重新登录，受限内容不展示 |
| `not_found` | 后端返回资源不存在 | 显示内容无法找到，提供返回档案入口 |

### 现有接口

所有路径前缀为 `/api/v1`，业务接口由后端校验 Cookie 会话和归属。错误结构为 `{"error":{"code":"…","message":"…"}}`。

| 方法与路径 | 请求 | 成功结果与用途 |
| --- | --- | --- |
| POST `/auth/login`、`/auth/logout` | 登录提交 `code`，退出无正文 | `ok`，后端设置或撤销 HttpOnly Cookie |
| GET `/me` | 无 | `owner_id`、`voice_ready`、`writing_ready` |
| GET、POST `/profiles` | 创建含 `elder_name`，可选 `birth_year`、`hometown`、`family_names`、`topics_want`、`topics_avoid` | 列表 `items`；创建返回 `id`、`elder_name` |
| GET `/profiles/{id}` | 档案 ID | 档案字段、`calls`、每通的 `chapters`、原话、核对事项 |
| POST `/profiles/{id}/photos` | multipart `file`，JPEG/PNG/WebP，最多 10 MB | `id`、`content_type`；后端验证真实格式 |
| POST `/calls` | `profile_id`、`consent` | `id`、`status`，同意与服务可用性均由后端检查 |
| WebSocket `/calls/{id}/live` | 现有音频和 `stop` 消息 | `ready`、音频、文字、`done`、`error`；关闭连接后核实保存结果 |
| GET `/calls/{id}` | 通话 ID | `status`、`failure_code`、`texts` |
| GET `/calls/{id}/audio/{kind}` | `kind=user` 或 `assistant` | 有权访问的 WAV 音频；缺失时显示无录音 |
| POST `/calls/{id}/draft` | 通话 ID | 当前同步返回章节 ID 与 `chapters`，保留兼容性 |
| POST `/facts/{id}` | `status=open/confirmed/rejected`、可选 `detail` | `ok`；确认、排除或补充核对内容 |
| POST `/paragraphs/{id}/score` | `score=1/2/3` | `ok`；保留已有评价能力 |

### 前端交付必须补齐的后端衔接

阶段 3-1 增量增加整理任务创建和查询接口，路径为 POST `/calls/{id}/draft-tasks`、GET `/draft-tasks/{id}`。任务包含 `id`、`call_id`、`status`、`step`、`chapter_ids`、`error`、时间字段，时间使用带时区的 ISO 8601。任务与所属家庭、通话一起持久化；同一通话只有一个执行中的整理任务。请求使用幂等标识，重复请求返回同一任务；超时先查询原任务，禁止直接再次调用模型。既有同步接口保持兼容。服务重启后任务须能继续或明确标记可重试失败，已经完成的步骤保留。前端使用真实任务结果替换当前仅存在于组件内的“正在写”。

通话创建补充幂等保护；未授权麦克风或连接失败时关闭相应通话记录。录音持续保存可恢复片段，明确结束与异常断开都释放 MediaStream、AudioContext、播放队列和连接。重新连接恢复查询与已保存内容；重新采集声音必须由老人再次操作。阶段 3-2 完成断网、刷新、服务重启和并发重试的完整检查。

读取照片需补充有归属校验的列表与预览接口；通话详情补充时间、录音是否存在、整理任务 ID，供历史记录与恢复入口使用。原话没有精确音频时间范围时显示整段播放，逐句点播须有可靠时间范围才提供。AI 问话的时间排序按 D18 补齐并用真实录音核对。

普通读取请求超时 15 秒，可显式重试；任务查询间隔从 2 秒逐步延长至最多 10 秒，隐藏页面暂停，返回页面立即查询，终态停止。写入请求不得自动重复提交。会话过期先重新登录，再按原 ID 查找记录。覆盖已有章节前说明影响并确认，成功后原子替换，失败保留原章节及核对信息。

## 5. 页面与产物

| 页面 | 路由 | 内容与主操作 |
| --- | --- | --- |
| 登录 | `/` | 邀请码、登录、会话过期说明 |
| 家庭档案 | `/profiles` | 已有档案与建档表单；补齐出生年；保存后进入对应档案 |
| 回忆录首页 | `/profiles/[id]` | 当前书封、书名、章节数量、继续访谈、目录与照片；支持切换回忆录 |
| 章节阅读 | `/profiles/[id]/chapters/[chapterId]` | 正文、关联照片、原话和原声；管理者核对与选择展示内容 |
| 家人 | `/profiles/[id]/family` | 所选章节、邀请、成员权限和留言；同一 Wi-Fi 下访问 |
| 我的 | `/account` | 当前身份、老人资料、相册、访谈记录、使用帮助、保存与隐私、退出登录 |
| 老人通话视图 | `/profiles/[id]?view=call` | 老人姓名、AI 身份与录音说明、同意、开始/结束、连接状态 |
| 历史定位 | `/profiles/[id]?call=<id>` | 定位指定通话和整理状态，刷新可恢复；不把姓名与原话写入 URL |

代表页面为回忆录首页、章节阅读与家人页。首页用书封、真实照片、目录和继续讲述入口组织内容；章节正文具有独立阅读空间。管理者通过明确入口进入老人通话视图；通话过程中仅显示通话相关内容。录音、转写、章节、记忆和照片的真实可用情况由接口提供；“待人工审校”内部状态不展示。详细布局与空状态见设计参考文档。

### 家人阅读与权限

管理者选择章节与照片，预览家人阅读效果后确认展示；原声单独授权。默认阅读内容只含选定正文与照片。家人以独立成员身份加入，能够阅读获准内容、留言并删除自己的留言；管理者能够撤销邀请、移除成员和取消展示。留言独立保存，正文更新经过管理者确认。邀请只由管理者主动复制交给家人。

实施需增加书籍展示版本、家庭成员、邀请和章节留言的数据与接口，逐次验证所属家庭、成员权限和展示范围。邀请默认一次使用、7 天有效，服务端只保存令牌摘要，兑换后签发 HttpOnly Cookie；撤销成员后现有会话也失去访问权限。展示版本须明确章节与照片列表，录音权限单独记录。原始逐字稿和内部核对内容不通过家人接口返回。

产品经理已确认阶段 3-2 支持同一 Wi-Fi 下邀请家人阅读和留言。邀请页面说明设备连接同一 Wi-Fi、电脑保持运行。以后部署上线支持异地访问，沿用成员与权限机制，访问入口由部署配置生成；部署和费用另行确认。

新增接口均以 `/api/v1` 开头：POST `/profiles/{id}/invitations` 接收章节、照片与原声权限，返回邀请 ID、一次性地址、到期时间；POST `/invitations/redeem` 接收令牌和称呼，返回成员身份并签发会话；GET `/profiles/{id}/members` 返回成员；DELETE `/invitations/{id}` 撤销邀请；DELETE `/profiles/{id}/members/{memberId}` 撤销成员；GET `/profiles/{id}/reading` 返回获准的展示版本；GET、POST `/chapters/{id}/comments` 读取或提交留言；DELETE `/comments/{id}` 删除获准管理的留言。写入具备幂等保护，错误使用统一结构。邀请令牌不进入日志，兑换后清除浏览器地址中的令牌，邀请入口禁用第三方资源并设置 Referrer-Policy。已有数据保持原归属，管理者身份与成员身份分开验证。完整字段、错误码、身份迁移与隔离测试在阶段 3-2 开发文档定义。

核心验收：登录 → 建档与照片 → 老人同意 → 连续通话并打断 → 结束与录音回放 → 全量转写和章节 → 对照原话及处理核对事项 → 下一次通话带入上次内容 → 刷新和服务重启后仍能读取数据。

| 子阶段 | 实施与验收 |
| --- | --- |
| 3-0 | 本声明、状态台账与是否表；产品经理确认页面组织、视觉默认值和子阶段安排 |
