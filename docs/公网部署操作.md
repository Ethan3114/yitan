# 公网发布操作

只操作环境 `xhs-titile-d0g1g5e3481a57b71` 内的 `yitan-api`、`yitan-web` 和 `yitan-worker-timer`。2026-11-12 只读核实当前套餐为个人版，到期 2026-12-12，超限按量已开启；发布脚本不修改套餐和计费开关。两个容器均为 0.25 核、0.5 GiB，实例范围 0～1。实例缩容有空闲等待时间，资源点按实际计算、存储、请求和流量消耗；模型调用由相应供应商另行计费。

## 本机发布工具

从项目根目录安装部署工具；这些依赖仅在本机使用，不进入产品容器：

```bash
npm install --prefix .intermediate/deploy-tools @cloudbase/cli@3.8.7 @cloudbase/manager-node@5.10.4 dotenv@17.3.1 --save-exact
backend/.venv/bin/pip install -r scripts/requirements-deploy.txt
```

`scripts/prepare_deployment.py` 按明确文件清单生成 `.intermediate/deployment/backend` 或 `frontend`，只包含运行源代码和容器构建文件。不会读取 `.dockerignore` 来决定上传范围。每个文件扫描本机密钥值，生成含 SHA-256 的发布清单；发现密钥、符号链接或缺失构建文件立即终止。

```bash
backend/.venv/bin/python scripts/prepare_deployment.py backend
backend/.venv/bin/python scripts/prepare_deployment.py frontend
```

## 运行配置

原始配置从 `backend/.env` 读取。生成的 `backend/.env.deploy`、`frontend/.env.deploy` 均被 Git 忽略、权限为 0600。共享代理密钥、工作任务密钥和登录限流摘要密钥只在首次生成，更新域名时保持一致。

```bash
backend/.venv/bin/python scripts/prepare_cloud_environment.py --web-origin https://前端实际域名 --backend-origin https://后端实际域名
```

首次创建时平台尚未分配域名，可先使用 `https://unconfigured.invalid` 完成服务创建；该配置下产品接口无法通过来源检查。取得域名后，重新生成实际配置，再更新现有镜像配置，完成验证后才公布入口。

## 发布服务

发布脚本调用官方 manager-node SDK，通过现有 CLI 登录在内存中取得临时凭据；服务端密钥和环境变量值不会进入命令行或输出。首次创建请求同时写入全部环境变量与最小规格。

```bash
node scripts/deploy_cloudrun.mjs --service yitan-api --config backend/.env.deploy
node scripts/deploy_cloudrun.mjs --service yitan-web --config frontend/.env.deploy
```

只检查登录和现有服务、不修改云端：

```bash
node scripts/deploy_cloudrun.mjs --service yitan-api --inspect
```

只调整域名等配置时复用最新镜像：

```bash
backend/.venv/bin/python scripts/configure_cloudrun.py yitan-api --file backend/.env.deploy
backend/.venv/bin/python scripts/configure_cloudrun.py yitan-web --file frontend/.env.deploy
```

前端容器使用自定义 Node 服务保留 WebSocket 转发。所有业务 API 经前端转发；前端覆盖代理密钥、真实来源 IP、协议与域名。后端必须在云端验证 `x-proxy-secret`，只在验证成功后信任 `x-client-ip`。Cookie 由后端使用 Secure、HttpOnly、SameSite=Lax 保存。WebSocket 要求来源等于正式前端域名。

## 后台任务触发

`yitan-worker-timer` 使用 Nodejs20.19、128 MB、900 秒超时；每 12 小时检查 `yitan_draft_tasks`，触发器为 `yitan-worker-every-twelve-hours`，表达式为 `0 0 */12 * * * *`。队列有待处理任务或已失去租约的任务时，调用 `WORKER_URL`，携带 `X-Worker-Token` 并持续读取服务端 SSE 心跳。空队列直接结束，不请求业务容器。任务领取、状态与步骤恢复由后端数据库事务保证。

用户提交整理时会立即尝试处理。当前处理器每次只领取一项任务，有实际访谈或另一个整理任务时暂不领取；长任务分段后也会重新排队。这些排队任务依赖定时恢复，等待可能接近 12 小时。正在处理的任务继续保持 20 秒续租；通话中的 20 秒保存也继续执行。

```bash
backend/.venv/bin/python scripts/deploy_worker_timer.py
```

仅更新已有函数的触发周期，使用以下命令；它会核实新配置，移除已有的旧周期触发器，确认只剩一个目标触发器，并比较函数运行配置：

```bash
backend/.venv/bin/python scripts/deploy_worker_timer.py --update-schedule
backend/.venv/bin/python scripts/deploy_worker_timer.py --inspect
```

该脚本将运行配置保存在本机 `.intermediate/private/timer-cloudbaserc.json`，函数上传目录仅包含 `deploy/worker-timer` 的代码。函数没有对外 HTTP 路由；还需验证匿名客户端无法主动触发函数，并实际验证离开页面后队列能够继续处理。

## 资源用量核查

2026-11-12 16:56 的只读审计中，原套餐日期窗口已上报的共享环境用量共 3123.32 点：PostgreSQL 2576.81 点（计算 2576.63，存储 0.18）、云托管 535.78 点、云函数 4.50 点、API 调用 5.53 点、HTTP 调用 0.70 点。数据库占 82.50%。这些是环境总量，包含共用环境的其他产品，无法全部归因忆谈。升级日的新旧按日期窗口存在重叠，不能相加；用量明细存在统计延迟。

共享 PostgreSQL 以 5 分钟为计量窗口，窗口内有访问或内部处理即按 0.5 核计量。上海单价为 342 点／核小时，一个活跃窗口为 14.25 点。每 5 分钟空查一次队列可覆盖全部计费窗口；实际账单中多个小时恰为 1800 核秒、171 点，忆谈函数同期每小时 12 次。定时函数本身每次平均约 1～3 秒，其数据库查询存在持续激活计算用量的机制。

仅考虑空队列巡查，且没有用户、其他产品或数据库内部处理时，旧频率的条件算例为 4104 点／天，新频率为 28.5 点／天。这是排除其他访问后的理论值，不作为实际节省承诺。数据库、账号、原声与回忆录应保留；降低活跃业务中的续租或保存频率不能按相同比例减少数据库计费窗口。

可减少的其他请求包括可见活跃页面 15 秒埋点（可调整为 60 秒）、整理进度 2～10 秒查询（可调整为 30 秒）及管理后台的重复全量历史查询（可改为汇总或缓存）。这些本轮仅评估。通话保存、任务续租和真实业务读写继续保留。实际书写与转写由供应商另行计费，和 CloudBase 资源点分别核算。

只读复核命令如下；结果仅保存安全计量字段至忽略目录，目录 0700、文件 0600，不打印环境变量或凭据：

```bash
backend/.venv/bin/python scripts/audit_cloud_costs.py --previous-start 2026-11-05 --previous-end 2026-12-05 --day 2026-11-12
```

审计使用官方资源点明细、忆谈专用函数监控及服务配置。当前新旧服务版本的运行副本均为 0，没有旧版本持续运行的证据。新触发器已通过 SCF `ListTriggers` 核实为 `Enable=1`、`AvailableStatus=Available`，旧周期触发器已不存在；空队列函数真实调用返回 `idle`，未调用模型。

计量依据：[PostgreSQL 计费窗口](https://cloud.tencent.com/document/product/876/120713)、[上海资源点单价](https://cloud.tencent.com/document/product/876/127357)。
